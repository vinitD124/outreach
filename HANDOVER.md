# Outreach — handover

Written for an AI coding agent picking this repo up cold.

Read this, then `lib/templates.js` and `lib/categories.js`. Those two files
hold the only architectural idea in the project that is easy to break.

---

## 1. What this is

A cold-outreach portal. For each business we want as a client, it builds a
**personalised one-page demo website**, then emails or WhatsApps that business
a link to it. The pitch is "here is a site I already made for you", so the demo
must carry *their* name and never ours.

The loop:

```
import leads (CSV/XLSX)  ->  each lead gets a slug
        |
        v
/{slug}  renders a template with that lead's details substituted in
        |
        v
/api/email  sends the pitch, links to /{slug}
        |
        v
lead opens it  ->  demovisited flips true  ->  visible in /admin
```

Two verticals so far:

| Category | Code | Business | Person | Templates |
|---|---|---|---|---|
| `clinic` | CLI | Clinic name | Doctor | `classic`, `micare` |
| `interior` | INT | Studio name | Principal designer | `interior`, `forma` |

## 2. Stack

- **Next.js 16.3.3**, App Router, Turbopack. React 19.
- **Postgres (Neon)** through `pg`, one `Pool` in `lib/db.js`. No ORM, no
  migration tool — schema changes are run by hand against Neon.
- **nodemailer** over SMTP for sending.
- **Tailwind v4** for the admin UI. The demo templates are plain
  HTML/CSS/JS in `public/` and use none of it.
- Deployed on **Vercel**. Branch `main` auto-deploys.

## 3. Data model

One table, `leads`. There is no migration file; this is the shape the code
expects:

| Column | Notes |
|---|---|
| `id` | pk |
| `slug` | the public demo URL, `/{slug}`. Generated from the name + 5 random chars |
| `clinicname` | the **business** name, whatever the vertical. Not renamed for historical reasons |
| `doctorname` | the **person**. Same |
| `phone`, `whatsapp`, `email`, `address` | contact |
| `category` | `clinic` \| `interior` |
| `template` | which demo layout |
| `emailsent`, `emailsentat`, `whatsappsentat` | send state |
| `demovisited` | flipped true on first view of `/{slug}` |
| `createdat` | sort order for the dashboard |

**`category` and `template` may not exist on an old database.** Reads that
touch them catch Postgres error **`42703`** ("column does not exist") and fall
back to the defaults, so a deploy landing before the manual migration degrades
instead of throwing. `lib/categories.js` and `app/admin/actions.js` both do
this. Keep the pattern if you add a column.

## 4. The one architectural rule

**A category declares nothing about templates. A template declares its
category. Everything else is derived.**

`lib/templates.js`:

```js
forma: { id: 'forma', category: 'interior', label: 'Forma',
         file: 'public/forma/index.html', base: '/forma/' },
```

`lib/categories.js` then derives the allowed list:

```js
templatesFor(categoryId)          // templates that declared this category
templateForCategory(categoryId)   // the first one = the default
templateFor(category, wanted)     // the ONLY place a template is decided
isTemplateMismatch(category, want)
```

`templateFor` honours `wanted` only if it belongs to that category, otherwise
it returns the category's default. **Every write path goes through it** — the
add-lead form, the import, the bulk template change. That is what makes "a
clinic on the interior demo" unrepresentable rather than merely discouraged.

Consequences to respect:

- Adding a template = one entry in `TEMPLATES` + a renderer + a `load.js`
  branch + a `next.config.mjs` trace entry. Nothing else. Do not add it to a
  list of allowed templates somewhere, because no such list exists.
- `DEFAULT_TEMPLATE` must stay `classic` and `DEFAULT_CATEGORY` must stay
  `clinic`. Every row written before those columns existed reads as those, and
  every demo link already sitting in somebody's inbox resolves through them.
- `resolveTemplate()` never throws and never returns undefined.

## 5. How a demo is rendered

`app/[slug]/route.js` — `force-dynamic`:

1. `SELECT * FROM leads WHERE slug = $1`
2. flip `demovisited` (fire and forget)
3. `resolveTemplate(lead.template)` → pick a renderer
4. `loadTemplateHtml(id)` reads the template's HTML off disk
5. the renderer substitutes the lead in
6. serve with a fixed set of security headers

`app/admin/preview/[template]/route.js` does the same against a hard-coded
`SAMPLE` lead, so you can look at any template without spending a lead:

```
/admin/preview/forma
/admin/preview/forma?clinic=Shreeji%20Interior%20Studio&doctor=Ar.%20Mihir%20Patel
```

### 5a. `lib/render/load.js` — do not refactor this

Every branch spells its path out literally:

```js
if (id === 'forma') {
  return fs.readFileSync(path.join(process.cwd(), 'public', 'forma', 'index.html'), 'utf-8');
}
```

Next traces filesystem access **statically** at build time. A variable, a
lookup table, even a small helper that returns the path, and it gives up and
pulls the whole project into the serverless bundle — `public/` and all its
template assets included. Slow deploys, and it can trip Vercel's size limit.

`next.config.mjs` must also name each template HTML in
`outputFileTracingIncludes`, because a file under `public/` is otherwise
treated as a CDN asset and left out of the function entirely.

### 5b. The renderer pattern

`lib/render/{classic,micare,interior,forma}.js`. `micare` swaps a single JSON
data object. The other three do **ordered string substitution** against
placeholder values the template ships with:

```js
const PLACEHOLDER = { brand: 'FORMA', email: 'studio@forma.design', ... };
```

Rules that matter:

- **Longest form first.** Substitute the long address before the short one, or
  the short match eats part of the long string.
- **Escape.** `escapeHtml` on anything going into markup; a separate
  `encodeURIComponent` pass for values inside a `wa.me` prefill.
- **Never invent.** A field we do not have is blanked, and the elements
  carrying it are hidden by injecting a `[data-req="email"]{display:none}`
  rule into `<head>`. A studio with no email must not show a made-up one.
- **`<base href>`** is injected so the template's relative `assets/`, `css/`,
  `js/` resolve from its own folder rather than from `/{slug}`.

## 6. Auth

- `proxy.js` (this Next version's middleware) matches `/admin/:path*` and
  `/api/:path*` and redirects/401s without a valid session.
- `lib/auth.js` signs the cookie as `expiry.HMAC(expiry, ADMIN_PASS)`, Web
  Crypto so it runs on Edge. It used to be the literal string
  `authenticated`, which anyone could set from the console.
- `app/api/email/route.js` **checks the session again itself**. It sends real
  mail on real credentials and should not depend on a matcher pattern in
  another file staying correct. Keep that second check.

## 7. Sending

`app/api/email/route.js` + `render.js` (HTML email) + `theme.js` (per-category
palette) + `lib/pitch.js` (subject, body, WhatsApp copy per category).

Guards worth keeping:

- **Refuses to send if `APP_URL` is missing or points at localhost.** The demo
  link would be dead on arrival and a cold email cannot be unsent.
- `lib/pitch.js` addresses people per category — a clinic contact gets
  "Dr. X", an interior contact gets the bare name, because a designer is not a
  doctor.
- **Clinic email output must stay byte-identical.** The per-category work was
  added underneath it; do not "tidy" the clinic branch.

`lib/test-leads.js` lists our own inboxes. Test sends skew every statistic
(we always open our own demos), so the table hides them and the header counts
them — which is exactly why the list lives in one shared module.

## 8. The Forma template (`public/forma/`)

The newest and most involved. Single page, no framework, ~6 scripts.

| File | Role |
|---|---|
| `index.html` | the whole page |
| `app.js` | journal + project dialogs, inquiry form |
| `motion.js` | scroll choreography; rebuilds the hero into the "portal" layout |
| `atelier.js` | index overlay, project directory, manifesto stamp |
| `study.js` | the drawing↔photo comparison slider |
| `plan.js` | the axonometric room that builds itself, projected from metres |
| `boot.js` | the title sheet shown on load |
| `hero-refine.css` | loaded **last**; most overrides live here |

Things that will bite you:

- **The scripts read the studio name off the header mark**
  (`document.querySelector('.brand').textContent`), not from their own copy.
  That is why substituting the HTML also reaches the page curtain, the index
  dialog, the footer signature and the inquiry filename. Keep it that way.
- **Interpolation trap.** Some markup is built in template literals and some
  in single-quoted concatenation. Putting `'+VAR+'` inside a backtick string
  renders it *literally* — this shipped once. Check the delimiter first.
- **`--len` on `<html>`** is the studio name's length, written by the
  renderer. Every display wordmark (title sheet, header, footer signature,
  page curtain) scales off it, because they were all drawn for the five
  letters of "FORMA". Verified from 5 to 52 characters at 1440 and 520.
- **No location is shown anywhere, deliberately.** Not the template's, not the
  lead's. A scraped address is often imprecise and a wrong street on
  someone's own website is worse than none. Do not helpfully add it back.
- **Single page only.** `project.html` and `credits.html` were deleted: the
  renderer never touched them, so they showed our brand and our city to the
  lead. Project cards open an in-page dialog. Any new sub-page has the same
  problem — solve it in-page, or route it through the renderer.
- **Two-way scroll animation is a product requirement.** Every section must
  animate in *and* out. No `observer.unobserve()` — use
  `classList.toggle(cls, e.isIntersecting)`. There are currently zero
  `unobserve` calls in the template; keep it that way.
- **`animation-fill-mode`**: never `both` on anything whose value is also
  driven from the scroll loop. A retained end state outranks the inline value
  and the effect freezes. Use `backwards`. This cost several hours.
- Never let a page's *visibility* depend on JS removing a class. The hero
  headline once did, and a failure meant a headless hero. It is a delay now —
  it can run late, never not at all.

## 10. Environment gotchas (Windows dev box)

These are about the machine, not the code, and each one cost real time:

- **`npm run build` can die with `0xc0000142`.** That is process creation
  failing under memory pressure, not a code error. This box has 8 GB and
  Chrome routinely holds 2 GB. Close Chrome, `rm -rf .next`, retry.
- **Bash heredocs eat one level of backslash.** `\\n` in a quoted heredoc
  arrives as a real newline; `\"` arrives as `"`. A patch script written that
  way silently fails to match, or produces broken JS. Write patch scripts with
  the file-writing tool instead of a heredoc.
- **Headless Chrome lies about animation.** `document.timeline.currentTime`
  freezes around 1 s while `performance.now()` keeps going, and
  `requestAnimationFrame`-driven scroll handlers are frequently starved. A
  screenshot showing a half-drawn line or an invisible headline is usually the
  harness. Verify with computed styles, and **re-run a failing check several
  times** before believing it.
- **Verify against rendered text, not HTML source.** Scraping
  `document.body.innerText` for leaked placeholder tokens catches broken
  interpolation that every string-level assertion passes. That is the check
  that would have caught the `'+PLACE+'` bug first time.

## 11. Conventions

- **No explanatory comments in code.** Comment *why*, never *what*, and keep
  it short. The reasoning goes in the commit message and the reply.
- Commit messages are prose explaining the decision and its consequence, not
  a bullet list of files touched.
- Placeholder/sample data in the repo is obviously fake. Nothing invented is
  ever shown to a lead.
